### ADR-0005 생명주기 호출은 단일 스레드로 제한한다
- 상태: 채택
- 날짜: 2026-11-09
- 배경: attach/detach, activate/deactivate는 트리 구조와 상태를 바꾼다. 여러 스레드에서 호출되면 순서가 꼬이고, JVM·Native·JS의 메모리 모델 차이 때문에 타깃마다 결과가 달라질 수 있다.
- 결정: Router와 Interactor의 생명주기 메서드는 하나의 스레드(앱에서는 메인)에서만 호출한다고 계약으로 정하고, 내부에 락을 두지 않는다. 비동기 작업은 활성 스코프 안에서 다른 디스패처로 보낼 수 있지만, 생명주기 호출은 다시 그 스레드로 돌아와서 한다.
- 고려했던 대안:
  (1) 내부를 락이나 원자적 연산으로 스레드 안전하게 만들기: 호출 측이 자유롭다. 하지만 JS에는 필요 없고, 콜백이 다시 들어오는 순서까지 보장하기 어려워 기각했다.
  (2) 모든 생명주기 메서드를 `suspend`로 만들고 내부에서 디스패처를 전환: 안전하다. 하지만 원본 API(동기 호출)와 어긋나고 플랫폼 UI 콜백에서 부르기 번거로워 기각했다.
- 결과: 구현이 단순하고 원본 시그니처를 유지하며, 테스트 결과를 결정적으로 만들 수 있다. 반면 잘못된 스레드에서 호출하는 실수는 컴파일러가 잡지 못한다. 필요하면 나중에 디버그 빌드용 스레드 검사를 추가한다.
- 관련: ADR-0002
