### ADR-0016 클립보드·파일 같은 플랫폼 입력은 뷰가 다루고, 결과 하나만 뷰 동작으로 넘긴다
- 상태: 채택
- 날짜: 2026-11-26
- 배경:
  - 실제 앱에는 클립보드 복사와 파일 선택·끌어다 놓기가 필요하다. 지금 샘플의 뷰 계약은 버튼 누름만 리스너 호출로 넘긴다. (이슈 #6의 5번)
  - 클립보드와 파일은 플랫폼마다 API, 권한, 실패 방식이 다르다. 웹은 `navigator.clipboard.writeText`(보안 컨텍스트와 권한이 필요하고 거절될 수 있다), `<input type="file">`, `drop` 이벤트다. Android는 `ClipboardManager`·`ActivityResultContracts`, iOS는 `UIPasteboard`·`fileImporter`다.
  - 공유 코드에는 플랫폼 타입을 두지 않는다(AGENTS.md). carti-RIBs-Swift는 ADR-0035로 같은 일을 했다.
- 결정:
  - 뷰가 플랫폼 API를 부르고, 공유 코드에는 결과 하나만 `TodoPresentableListener` 호출로 넘긴다. Interactor는 결과에 따라 상태를 바꿔 `render`한다.
    - 클립보드: `didCopyList(succeeded: Boolean)`. 뷰가 목록 제목들을 줄바꿈으로 이어 클립보드에 쓰고 성공 여부만 알린다.
    - 파일: `didReceiveFile(name: String, text: String)`. 선택과 끌어다 놓기는 같은 호출 하나로 간다. Interactor가 줄마다 앞뒤 공백을 지우고 빈 줄을 건너뛰어 할 일로 더한다. 새 id는 지금 가장 큰 id 다음부터다.
  - 결과 문구는 `TodoViewState.notice`에 넣는다. Interactor는 한 번 그린 뒤 지우므로 다음 동작으로 다시 그리면 사라진다.
  - 외부 입력의 크기는 두 곳에서 막는다. 뷰는 파일의 앞 64KB만 읽어 넘긴다. 공유 코드는 한 번에 100개(`TodoInteractor.MAX_IMPORTED_TODOS`)까지만 더하고 건너뛴 줄 수를 알린다.
  - 목록을 불러오기 전에는 파일에서 더하지 않고 그렇다고 알린다. 뒤이어 불러온 목록이 덮어쓰기 때문이다.
  - 더한 할 일은 Interactor의 목록에만 있다. 서버에 보내지 않는다(쓰기 API는 ADR-0014에 있지만 이 예시의 범위가 아니다).
  - 이번에는 웹 뷰만 버튼·파일 선택·끌어다 놓기를 둔다. React 순수 뷰가 브라우저 API를 직접 부르고, Kotlin 어댑터(`WebTodoView`)는 결과를 리스너로 옮기기만 한다(ADR-0009, ADR-0011). Android·iOS 뷰는 새 동작을 보내지 않는다. Android 어댑터는 상태 생성자만 맞춘다.
- 고려했던 대안:
  (1) 공유 코드가 `ClipboardWriter` 같은 인터페이스를 Dependency로 받아 직접 부르기: Interactor 테스트에서 가짜로 바꾸기 쉽다. 대신 권한, 사용자 제스처 안에서만 되는 제약(웹), 포커스 같은 뷰의 사정이 공유 코드로 새고, 플랫폼마다 구현과 Swift·JS 경계가 하나씩 는다(ADR-0006). 결과만 받으면 공유 코드는 성공·실패 두 경우만 안다. 기각.
  (2) 파일 내용을 `ByteArray`로: 바이너리 파일도 받을 수 있다. 이 예시는 줄 단위 텍스트라 디코딩을 뷰(`Blob.text()`)에 두는 편이 단순하다. 바이너리 업로드는 ADR-0014가 열어 둔 대로 따로 정한다. 기각.
  (3) 선택과 끌어다 놓기를 다른 호출로: 공유 코드가 할 일은 같다. 받는 방법은 뷰의 사정이다. 기각.
  (4) 별도 예시 화면에 두기: 피처를 건드리지 않는다. 대신 이 결정이 보여 줄 것은 실제 피처의 `리스너 호출 → Interactor → render` 흐름이다. 기각.
  (5) 복사할 텍스트를 공유 코드가 상태로 내려 주기: 형식을 공유 코드가 정할 수 있다. 지금은 제목을 잇기만 해서 상태 필드를 늘릴 이득이 없다. 형식이 플랫폼마다 같아야 하면 다시 본다. 보류.
- 결과:
  - 흐름 테스트 5개를 더했다(복사 결과 문구와 지우기, 파일 줄 처리, 100개 제한, 빈 파일, 불러오기 전). JVM·JS 통과.
  - 웹 Vitest 5개를 더했다. 클립보드는 `navigator.clipboard`를 테스트마다 넣어 성공·거절 두 결과를 만든다. 실제 OS 클립보드에 쓰이는지는 브라우저 권한과 포커스에 따라 달라 확인하지 않는다. 파일은 input `change`와 `drop` 이벤트로 넣고, 64KB 넘는 부분이 넘어가지 않는 것을 확인한다. jsdom의 `Blob`에 `text()`가 없어 테스트에서만 `FileReader`로 채운다.
  - 64KB에서 자르면 UTF-8 글자 중간이 잘려 마지막 글자가 대체 문자가 될 수 있다.
  - 파일 읽기가 실패하면 뷰는 아무것도 넘기지 않는다(거절된 Promise는 브라우저가 처리되지 않은 거절로 알린다).
  - Android·iOS에서 같은 입력을 붙이는 방법은 다루지 않았다. 계약은 그대로 쓸 수 있다.
- 관련: ADR-0006, ADR-0009, ADR-0011, ADR-0014, 이슈 #6, carti-RIBs-Swift ADR-0035
